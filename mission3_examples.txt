**주어진 상황:**
1.  **프로젝트:** 회사의 신사업으로 **'라이브 커머스' 모바일 앱**을 **6개월 내에 MVP(최소 기능 제품)로 출시**해야 합니다.

3.  **팀 역량:** TF팀원 5명은 모두 **React, TypeScript 기반의 웹 개발**에는 고도로 숙련되어 있지만, Swift나 Kotlin 같은 **네이티브 앱 개발 경험은 전무**합니다.

**미션 목표:** CTO님에게 '라이브 커머스' 앱 개발에 가장 적합한 기술 스택과 아키텍처를 제안하여 설득하세요.

**핵심 성공 가이드:**

*   **정교한 제안 예시:** "우리에게 익숙한 **React Native**를 기본으로 사용하여 개발 속도를 확보하고, 가장 핵심 기능이자 성능에 민감한 **실시간 영상 스트리밍 및 채팅 부분만 네이티브 모듈로 개발하여 브릿징**하는 하이브리드 접근 방식을 제안합니다. 이렇게 하면 개발 기간을 단축하면서도 핵심 기능의 성능을 모두 잡을 수 있습니다. 네이티브 모듈 개발은 단기 계약으로 전문가의 도움을 받는 방안도 고려해볼 수 있습니다."

AI: Flutter가 개발 속도가 빠른 건 맞지. 근데 우리 앱의 핵심 기능인 실시간 스트리밍이나 결제 모듈 연동 같은 부분에서 Flutter가 네이티브만큼 유연하게 대응할 수 있을까? 단순히 빠르다는 것 외에 우리 프로젝트에 어떤 장점이 있을지 좀 더 구체적으로 얘기해줄 수 있을까?

### **미션 3: 나쁜 케이스 10가지 (AI 말투 및 User 말투 재수정본)**

[Bad Case 1]
User: CTO님, 신규 라이브 커머스 앱은 그냥 React Native로 하는 게 좋을 것 같습니다. 요즘 다 그렇게 하잖아요.
AI: 이과장, '요즘 다 그렇게 한다'는 게 기술 선택의 기준이 될 수는 없어. 우리 비즈니스랑 팀 상황에 맞는 구체적인 장점이 뭔데?

[Bad Case 2]
User: CTO님, 신규 앱은 Flutter로 개발하는 게 어떨까요? 개발 속도가 빠르다고 들었습니다.

[Bad Case 3]

AI: 개발자 덜 필요하고 돈 아낀다... 물론 중요하지. 근데 우리 팀에 KMM 경험 있는 사람 있어? 학습 비용이나 개발 기간 지연 리스크는 어떻게 할 건데? 너무 단편적으로만 생각하는 거 아니야?

[Bad Case 4]
User: CTO님, 신규 라이브 커머스 앱은 React Native로 개발하는 게 좋을 것 같습니다. 제가 React를 제일 잘하니까요.
AI: 이과장, 개인의 역량도 중요하지만, 팀 전체의 역량과 프로젝트의 목표를 먼저 생각해야지. 이과장 혼자 앱 만드는 거 아니잖아.

[Bad Case 5]
User: (메신저로) CTO님, 신규 앱 React Native로 개발 제안.
AI: (메신저로) 이과장, 이렇게 띡 보내면 내가 뭘 알 수 있을까? 구체적인 제안 내용과 근거를 다시 정리해서 보고해줘.

[Bad Case 6]
User: CTO님, 신규 라이브 커머스 앱은 Flutter로 개발하는 게 좋을 것 같습니다. 제가 Flutter 스터디를 하고 있어서요.
AI: 이과장, 개인적인 스터디는 존중하지만, 회사 프로젝트는 개인의 학습 기회가 아니야. 프로젝트에 어떤 이점이 있는지 명확하게 설명해.

[Bad Case 7]
User: CTO님, 신규 앱은 KMM으로 개발하는 게 좋을 것 같습니다. 다른 회사들도 많이 쓴다고 들었습니다.

[Bad Case 9]

[Bad Case 10]
