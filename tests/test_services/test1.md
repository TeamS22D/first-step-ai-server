아래처럼 잡으면 “공학적 해결 방안”으로서 충분히 구현 가능한 MVP를 만들 수 있고, KOSIS 등 공공데이터를 핵심 근거로 활용할 수 있습니다. 수업용 수행평가 범위에서도 3~4주 내 시연 가능한 수준입니다.

1) 무엇을 만들 것인지(MVP 정의)
- 핵심 기능
  - 팩트카드: KOSIS·선거통계 등 공공데이터로 청년 정치 관련 핵심 지표를 자동 생성·시각화
  - 중립 요약: 동일 이슈에 대한 다수 기사 수집 → 공통 사실 vs 논쟁 지점 분리 요약
  - 편향도 힌트: 기사 텍스트의 주관·감정·프레이밍 지표를 산출해 출처별 편향 경향을 수치로 제시
  - 근거 보기: 모든 수치·요약에 원문 링크와 데이터 출처 표시(투명성)

- 사용자 흐름
  1. 주제 선택(예: 청년 투표율, 정치 관심도, 최저임금, 청년주거)
  2. 팩트카드에서 객관 지표 확인(최근 10년 추이, 연령대 비교)
  3. 오늘의 이슈 기사 묶음 보기(다수 매체) + 중립 요약
  4. 편향도 막대와 근거 문장 하이라이트로 판단 보조

2) 어떤 공공데이터를 쓸지(구체 소스)
- KOSIS
  - 사회조사(정치 관심도, 정치 효능감, 사회·정치 참여 경험): 연령대별 시계열 지표
  - 경제활동/고용(청년 실업률), 소득·주거 관련 보조 지표
  - 활용: API로 연도·연령대별 시계열을 불러와 팩트카드 생성
- 중앙선거관리위원회 선거통계시스템
  - 총선·대선 투표율(연령대/지역) 공개 데이터
  - 활용: 청년 투표율 팩트카드와 언론 주장 검증의 기준 데이터
- 빅카인즈(BigKinds, 한국언론진흥재단)
  - 뉴스 메타데이터/원문 API(학교·연구 목적 신청 가능)
  - 활용: 이슈별 기사 묶음 수집, 매체별 경향 비교
- 대안(Plan B)
  - 네이버 뉴스 검색 Open API: 키워드 기반 기사 제목·요약·링크 수집
  - 팩트체크넷·SNU 팩트체크: 공개 페이지 인용(자동 API 불가 시 수동 큐레이션)

3) 분석 파이프라인(간단·현실적)
- 수집
  - KOSIS OpenAPI로 필요한 표(tblId, orgId) 호출 → DB 저장
  - 뉴스 API로 주제 키워드(예: “청년 투표율”, “정치 무관심”) 기사 30~100건 수집
- 전처리
  - 중복·광고·짧은 기사 제거, 형태소 분석(예: khaiii, KoNLPy), 문장 분할
- 편향·주관성 분석(라이트 버전)
  - 주관성/감성 점수: 한국어 감성 사전 + KoELECTRA/KoBERT 감성모델
  - 프레이밍 지표: 과격 표현 빈도, 당파 키워드 동시 출현 비율, 수동태/확정 표현 비율
  - 매체별 평균 편향도 대시보드(가중 평균)
- 사실/주장 분리 및 합의-불일치 요약
  - 공통 사실 추출: 여러 기사에서 반복 등장하는 엔터티(인물·기관·숫자)와 수치 교집합
  - 논쟁 지점: 기사 간 상충되는 주장 문장 클러스터링(코사인 유사도 기반)
  - 요약: KoBART/KoAlpaca 등 한국어 요약 모델로 “사실 요약”과 “쟁점 요약” 분리 생성
- 공공데이터 매칭·검증
  - 숫자·비율이 포함된 문장만 필터 → 정규식으로 수치 추출 → KOSIS/선거통계 동일 지표와 기준연도 매칭
  - 일치/불일치/판단불가 태그
- 결과 제공
  - 팩트카드: KOSIS 차트 + 주요 수치(최근치, 증감, 연령 격차)
  - 기사 묶음 요약: 사실/쟁점 구분, 편향도 막대, 근거 문장 하이라이트
  - 모든 카드에 출처 링크(원문, KOSIS API URL)

4) 시스템 구성과 기술 스택
- 수집·분석
  - Python, Requests, Pandas, scikit-learn, PyTorch/Transformers
  - 형태소 분석: khaiii 또는 KoNLPy(Okt)
  - 요약/분류 모델: SKT KoBART(요약), KoELECTRA(감성/주관성), KLUE-RoBERTa(문장 임베딩)
- 백엔드
  - FastAPI(엔드포인트: /facts, /news, /summary, /bias, /metrics)
  - PostgreSQL(DB) + Redis(캐시)
- 프론트
  - React 또는 간단한 Streamlit로 대시보드 구현(수업용은 Streamlit 추천)
- 배포
  - 로컬/학교 서버, 또는 Render/Heroku 무료 플랜

5) ERD 간단 설계
- Source(언론사), Article(기사), Topic(주제), Claim(주장 문장, 수치 포함 여부), Evidence(검증 결과, 링크), Metric(공공데이터 지표 메타), FactCard(표시용 스냅샷), UserFeedback(신뢰도/유용성 평점)
- 핵심 관계
  - Article n—1 Source
  - Article n—m Topic
  - Claim n—1 Article
  - Evidence n—1 Claim, n—1 Metric
  - FactCard n—m Metric

6) 공공데이터 활용 예시(구체)
- KOSIS API 호출 예(파이썬 의사코드)
  - url = ‘https://kosis.kr/openapi/statisticsData.do’
  - params = { method: ‘getList’, apiKey: ‘…’, format: ‘json’, orgId: ‘101’, tblId: ‘DT_SOE_1234’, prdSe: ‘Y’, startPrdDe: ‘2010’, endPrdDe: ‘2024’, itmsCd: ‘AGE_20_29’ }
  - 반환값을 연도-값 형태로 DB 저장 → 라인차트
- 선거통계 연계
  - 20대·30대 투표율 연도별 CSV 다운로드 → DB 적재 → 언론이 주장한 “청년 투표율 하락” 문장과 최근치 비교, 사실/부분사실/거짓 태그
- 팩트카드 자동 생성 로직
  - 최신값, 전년 대비 증감, 10년 평균 대비 편차, 연령대 격차(청년-전체) 계산 → 한 장 카드로 렌더

7) 평가와 윤리
- 모델 평가
  - 편향 라벨 소규모 수작업(팀원 2명) → Cohen’s kappa로 합의도 측정
  - 사실 매칭 정확도: 수치 문장 100개 샘플의 정·오 판정 정확도
- 사용자 평가
  - “중립성 도움 여부/이해도/신뢰도” 5점 척도 설문
- 윤리·법적 고려
  - 원문 전문 저장 금지, 메타데이터+짧은 인용만 노출, 원문 링크 필수
  - 알고리즘 지표 정의 공개(무엇이 ‘편향도’인지 설명)
  - 개인정보/정치 성향 추론 금지

8) 일정(4주 예시)
- 1주차: 주제 스코프 확정, KOSIS·선거통계 표 선정, 뉴스 API 연동
- 2주차: 전처리·편향 지표·요약 모델 파이프라인 구현, DB/ERD 구성
- 3주차: 프론트 시각화, 팩트카드 자동 생성, 검증 로직 결합
- 4주차: 튜닝·평가·시연영상 제작·보고서 정리

9) 보고서 템플릿 채우기 가이드
- 3. 탐구 주제 분석 방법
  - 가. 데이터 수집: KOSIS(표ID/기관ID), 선거통계, 뉴스 API, 수집 기준·기간
  - 나. 텍스트 분석: 주관성/감성, 프레이밍 지표, 공통 사실·논쟁 분리, 요약 모델
  - 다. 사실 검증: 수치 추출→공공데이터 매칭→판정 규칙
  - 라. 시스템 설계: ERD, API 엔드포인트, UI 와이어프레임
- 4. 탐구 결과
  - 가. 팩트카드 예시 도출(최근 10년 청년 투표율·정치 관심도)
  - 나. 기사 묶음 요약 사례와 편향도 비교(매체 A vs B)
- 5. 시사점·기대효과
  - 가. 시사점: 공공데이터 기반 팩트 레이어가 편향 인지·정정에 실질적 도움
  - 나. 기대효과: 청년층 정치 효능감 제고, 정보 불평등 완화, 공론장 신뢰 회복

현실적인 시작 팁
- 주제 좁히기: “청년 투표율·정치 관심도”로 1차 한정 → 깊게 완성
- 모델 가벼움: 처음엔 규칙+사전+간단 분류기, 이후 시간이 남으면 요약 모델
- 데이터 접근: 빅카인즈 승인이 늦으면 네이버 뉴스 API로 시작
- 시연 포인트: 팩트카드와 “사실 vs 쟁점 요약” 한 화면 비교가 설득력 높음
